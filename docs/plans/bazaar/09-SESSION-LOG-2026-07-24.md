## 1. What the bazaar looked like before

The facilitator already aggregated ~26k discoverable resources from 12 external
facilitators — but it *mirrored* them rather than curating them. A full snapshot
plus a 300-URL stratified probe found:

| Finding | Measure |
|---|---|
| Items that actually answer HTTP 402 | **~19%** (~4,951) |
| Structurally unpayable (`accepts: []`) | 15.3% (4,026) |
| Junk URLs (fake schemes, localhost, templates) | 12.5% (3,269) — incl. **2,318** `monopoly://` |
| Host alive but resource gone (404/410) | ~62% — the dominant failure mode |
| Not updated in >30 days | 86.3% |
| Contributed by payai alone | 95.1% of catalog, ~96% of all junk |

Root cause in code: both feeders called `bulk_import(resources, skip_validation=true)`,
bypassing the SSRF guard and the non-empty-`accepts` rule that already existed.
There was no liveness check, no ranking, no tiers, and no delete path.

## 4. Things that were harder than they looked

**"Tangent" does not exist.** The requested VIP partner returned NXDOMAIN and
zero hits across CDP, PayAI, our own catalog, awesome-x402 and x402scan. The real
product matching "blogs for agents" is **Tenjin** (`tenjin.blog`) — already the
largest self-registered publisher in our bazaar. Confirmed with the user before
shipping the manifest.

**Execution Market `/tasks` is not listable.** Proved the ERC-8128 wallet signing
path works (fresh ephemeral key passes auth), then hit the real gates: body
validation → **ERC-8004 identity required** → payment. And EM's own manifest
declares `pricing.model = "bounty"` — the publisher sets the amount, paid at
completion, and the 402 carries no `payTo`. Listing it would have meant inventing
payment terms, so it was documented instead:
`docs/handoffs/2026-07-24-execution-market-bazaar-listing.md`.

**The verification badge took two fixes.** `getSummary` reverts with
`clientAddresses required` on an empty client set (→ verify identity via
`ownerOf` instead), and the cache was keyed by a URL synthesized from the
manifest that never matched the registry's trailing-slash URL (→ key by manifest
label).

**GitHub cancels intermediate queued runs.** A "cancelled" deploy looked alarming
but was benign: with `cancel-in-progress: false`, a newer queued run supersedes a
pending one. Confirmed the surviving run carried the same tree before moving on.

## 5. The regression I caused, and fixed

The read-route rate limit added in v1.56.0 was sized against an imagined attacker
(30 req/min per IP) rather than the endpoint's real access pattern. Walking a
21k-item catalog is ~212 requests at the 100/page cap, so **every legitimate
paginating client was throttled** — 502 × HTTP 429 in six hours, all on
`/discovery/resources`, with ALB 4xx stepping from ~176/h to ~309/h right after
the deploy.

Fixed in v1.57.1 (1 token/200ms, burst 120 ≈ 300 req/min); verified with 40
rapid paginated requests returning 40/40 × 200.

Worth recording precisely: this was reported as "the facilitator is throwing
500s", and it was not. Target 5xx totalled **3 responses in 12 hours** (503s from
ECS task replacement during the day's deploys) and **zero** `status=500` was ever
logged. Two things made it look like a 500: clients surfacing a 429 as a generic
failure, and our aggregator logging *outbound* upstream failures as
`ERROR ... HTTP 500` (questflow), which reads like our own error. Lesson stored in
memory as `feedback-rate-limit-pagination`.

**The misleading log was itself fixed (v1.59.2).** Upstream feed failures now log
at WARN with `direction=outbound`, `upstream_url` and `upstream_error`; only our
own responses carry `status=NNN`, so a grep can no longer conflate the two.
Internal failures (importing into the registry) remain ERROR. `CLAUDE.md` also
gained a "confirm before chasing" runbook: check ALB `HTTPCode_Target_5XX_Count`
first, then count our own status codes, and treat a few `503`s around a deploy as
ECS task replacement.

## 6. Security posture

An adversarial review produced 16 findings (F1–F16), consolidated in
`08-security-hardening.md`. The two blockers were fixed before the workstreams
that would have made them live:

- **F1** — a lookalike host (`api.meshrelay.xyz.evil.com`) could have inherited a
  curated tier through a naive string-prefix match, registerable through the
  public `/discovery/register`. Now host-exact + path-boundary on the parsed URL.
- **F2/F3** — the prober fetches attacker-supplied URLs; without a pinned
  connector it could have been steered at `169.254.169.254` and read the Fargate
  task role. Now resolve → reject-if-any-address-disallowed → pin → manual
  redirect re-checks, plus a port allowlist.

Also shipped: payTo-drift quarantine (hijack signal), feed-poisoning protections
in the merge (no `source` downgrade, manifest-authoritative payTo), future-timestamp
clamp, admin surface that is genuinely indistinguishable from nonexistent (404 on
malformed bodies too, not just valid ones), and length caps.
